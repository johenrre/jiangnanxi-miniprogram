# 小程序功能范围与后端对接规划

更新时间：2026-07-21

## 1. 文档目的与边界

本文用于回答三个问题：

1. 新版小程序目前已经有哪些功能，哪些逻辑仍需要补齐。
2. 设计师、创作者和分销功能中，哪些页面可能保留，负责人需要确认什么。
3. 当前 API 中哪些使用真实后端、哪些仍是 Mock、后端还需要提供什么。

本轮只做盘点和规划，不实现任何尚未确认的设计师、创作者或分销页面。DIY 不在本文的功能实现规划内，后续单独讨论。

旧版 `miniprogram-1` 仅用于核对页面、交互、接口和权限条件。本文不把“旧版存在”视为“新版必须迁移”。

接口状态说明：

- **真实且已返回**：当前测试后端已实际返回可解析的业务数据或明确空数据。
- **真实但待登录验证**：路由存在，未登录返回 401；必须先解决测试号登录才能继续验证。
- **真实接线但未调用**：新版已有真实接口代码，但开关仍固定为 Mock，未产生写操作。
- **Mock**：页面当前读取本地 Mock 或本地存储，不请求对应业务后端。
- **缺失**：当前测试后端返回 404，不能据此开发完整页面。

## 2. 当前结论

1. 首页、发现、商品详情、购物车、确认订单和个人中心的页面骨架已经存在，但主交易链路尚未完成真实后端闭环。
2. 公开作品列表接口可用：客订作品有数据，设计师作品当前为空。
3. 测试后端的微信登录返回 `400 / 微信小程序登录未启用`，因此资料、地址、订单等需要登录的真实流程暂时无法验收。
4. 购物车、商品选项、创建订单和支付当前仍使用 Mock；不会创建真实订单，也不会拉起真实支付。
5. 我的设计、订单和售后由同一个 Mock 开关控制，目前仍使用 Mock 数据。
6. 旧版的设计师、创作者、分销入口虽然保留了页面文件和路由，但个人中心中的整块入口实际被 `wx:if="{{false}}"` 隐藏。
7. 旧版“设计师”和“创作者”不是两套独立身份：用户先申请设计师身份，通过后进入创作者中心提交作品。
8. 旧版分销申请并没有完整接口实现，申请页实际直接进入分销面板；不能按成熟功能迁移。
9. 当前测试后端的创作者相关路由返回 404。未经负责人确认并由后端补齐契约前，不应创建对应新版页面。
10. 每日签到、我的邀请、我的卡券继续保持彻底删除，不得借分销功能重新引入。

## 4. 建议补齐的业务逻辑规划

### P0：先完成主购买闭环

这些逻辑与设计师、创作者、分销是否保留无关，应优先完成：

1. **测试登录可用**
   - 后端启用当前 AppID 的微信登录。
   - 提供专用测试账号，不使用正式用户。
   - 明确未登录、Token 过期、账号禁用、手机号授权取消的错误码。
   - 登录失败不得自动伪装成 Mock 成功。

2. **地址真实联调**
   - 验证列表、新增、编辑、删除、设默认。
   - 服务端保证同一用户最多一个默认地址。
   - 明确地址删除后订单快照不受影响。

3. **作品详情可直达**
   - 增加 `GET detail?id=...` 或让列表接口支持按 `id/design_code` 查询。
   - 分享链接、历史链接、刷新页面都不能依赖内存中的首屏列表。
   - 后端返回商品是否可售、实时价格、材料信息和作者身份。

4. **真实订单创建与幂等**
   - 客户端只提交商品、选项、数量、地址 ID 和备注；最终金额由服务端重算。
   - 创建订单必须支持幂等键，重复点击、超时重试不能生成多个订单。
   - 明确库存/商品失效、价格变更、地址失效、订单重复等业务错误码。
   - 当前测试后端契约一次只接受一个 `designId`，需要负责人确认是否允许多商品订单。

5. **支付状态闭环**
   - 支付参数创建与订单创建分开，后端记录统一商户订单号。
   - `wx.requestPayment` 成功回调不等于已支付，必须以后端查询结果为准。
   - 支持成功、取消、失败、超时、延迟到账、关闭和重复点击。
   - 真实支付只在具备支付能力的 AppID 和真机上验收。

6. **订单与售后真实联调**
   - 订单列表状态必须与创建订单、支付查询使用同一套枚举。
   - 售后接口需要返回申请状态、驳回原因、退款状态和时间线，而不是只修改本地列表。
   - 明确继续支付、取消订单、确认收货是否在本期范围。

### P1：完善展示和账户体验

1. 发现页分页、刷新和列表去重。
2. 首页轮播从临时网络图片切换为正式资源或正式配置接口。
3. 个人资料读取、头像上传和保存的真实联调。
4. 我的设计接真实数据，并确认详情、编辑、再次购买等后续操作。
5. 将“我的设计/订单/售后”的共用 Mock 开关按业务拆分，便于逐项联调；只在实际开始对接时修改，不建立额外配置平台。
6. 明确购物车采用本地存储还是服务端同步。若无需跨设备同步，本地购物车可以保留，但下单时仍须由后端重新校验商品和金额。

### P2：条件性角色功能

设计师、创作者、分销必须先完成第 5 节的负责人确认。未勾选的功能不建立路由、入口、接口、状态、资源或占位内容。

## 5. 设计师、创作者与分销保留确认表

### 5.1 旧版真实情况

- 设计师申请页：有未申请、审核中、已通过、已驳回四种状态。
- 创作者中心：只有认证身份才能查看统计、作品和提交入口。
- 作品提交：只能选择已支付、已发货或已完成订单。
- 作品审核：旧版显示审核中、已通过、被驳回，但作品详情点击只是提示作品 ID，详情/重提页面并未完成。
- 消息通知：有列表和标记已读，但旧版会吞掉读取失败。
- 公开设计师主页：无需登录，支持分享和作品进入商品详情，但专用公开资料接口当前不存在。
- 分销申请：旧版仓库中的申请和当前申请查询是空实现，页面直接跳转分销中心。
- 分销中心：展示邀请码、链接、二维码、下线、佣金、余额和提现。
- 个人中心的上述入口整体被隐藏，不能把旧版页面文件当作上线功能。

### 5.3 建议的产品决策方式

为了避免出现“有入口但没有完整业务”的半成品，建议从下面的组合中选择，而不是随意挑单页：

- **组合 A：全部不保留**。主购买链路不受影响，当前最稳妥。
- **组合 B：只保留公开设计师主页 D6**。适合展示作者品牌，但需要后端提供公开资料和作品接口。
- **组合 C：保留完整创作者链路 D1～D5，并决定是否增加 D6/D7**。必须同时具备审核和运营能力。
- **组合 D：保留完整分销链路 F1～F6**。必须先确定资格、归因、佣金、退款回滚、提现、风控和财务规则。

不建议只保留提现页、只保留作品提交页或只显示身份入口。

## 7. 后端对接前需要形成的契约

### 7.1 通用约定

1. 统一响应结构：`{ code, message, data }`。
2. HTTP 状态码与业务错误码不能互相替代：401 表示会话问题，403 表示无权限，404 表示资源不存在，409 表示重复/状态冲突，422 表示参数或业务校验失败。
3. 每个写接口都要定义幂等策略，至少覆盖创建订单、支付参数、售后申请、作品提交和提现。
4. 列表统一使用 `page/pageSize/total/list`，明确最大页大小和排序。
5. 时间统一返回可解析的时间戳或 ISO 时间，并标明时区。
6. 金额统一使用整数分，避免浮点金额。
7. 图片返回绝对 HTTPS 地址或统一相对路径规则。
8. 测试环境提供测试用户、测试商品和可回滚数据，不使用正式用户与正式商品。

### 7.2 主交易链路最少字段

| 领域 | 后端至少需要返回 |
| --- | --- |
| 作品/商品 | ID、设计码、标题、封面、作者、材料、基础价、可售状态、版本号 |
| 地址 | ID、收货人、手机号、省市区、详细地址、是否默认 |
| 订单 | ID、订单号、商品快照、选项快照、数量、金额明细、地址快照、状态、支付状态、创建时间 |
| 支付 | 商户订单号、支付参数、查询状态、关闭原因、支付完成时间 |
| 售后 | 售后单号、订单号、类型、原因、申请金额、审核状态、退款状态、驳回原因、时间线 |

### 7.3 如果保留创作者链路

后端至少需要：

- 当前申请查询、提交/重新提交申请。
- 身份状态与权限查询。
- 创作者面板统计。
- 可提交订单列表。
- 作品创建、列表、详情、修改/重提。
- 作品审核状态、驳回原因和发布时间。
- 通知列表、未读数、标记已读。
- 公开作者资料和已发布作品列表。
- 运营审核后台或明确的人工处理流程。

### 7.4 如果保留分销链路

负责人和后端必须先定义：

- 分销资格申请和审核状态。
- 邀请归因生效时点、有效期、防自邀、防重复绑定。
- 一级/二级关系是否保留，以及关系是否可变更。
- 佣金计算基数、比例、冻结期、退款回滚和订单完成条件。
- 可用、冻结、待结算、已结算余额。
- 提现门槛、手续费、实名信息、审核、打款、驳回和失败重试。
- 财务对账、风控和隐私合规。
- 分销邀请入口不得重新变成已删除的通用“我的邀请”。

## 8. 确认后的实施与验收方式

负责人完成第 5 节决定后，只为标记“保留”的功能安排开发。

每个确认页面单独完成以下验收：

1. 微信开发者工具真实编译，读取 Console 和运行时异常。
2. 同一机型下与旧版可观察行为对照，不复制旧版实现代码。
3. 登录/未登录或公开访问状态。
4. 加载、空数据、失败和重试状态。
5. 普通用户、待审核、已通过、已驳回、无权限等适用的权限状态。
6. 核心写操作的成功、失败、超时和重复点击。
7. 页面截图和核心点击流程截图。
8. 不重启现有微信开发者工具；不提交、不上传、不发布、不触发真实资金操作。

在负责人确认前，本轮不增加任何角色页面、入口、API、Mock、状态、资源或占位内容。
