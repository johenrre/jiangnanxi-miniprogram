# DIY 珠子阴影方案

## 目标

给新版 DIY 盘内珠子增加稳定、轻量的立体阴影，同时保持代码简单，避免把旧版复杂的质量切换、预热队列和多层 Canvas 带进来。

旧版 `miniprogram-1` 只用于观察效果和理解思路；新版不引用旧版源码，也不复制旧版构建产物。

## 新版采用的方案

只保留两种阴影：

- 普通圆珠：所有圆珠共用一张离屏阴影贴图。贴图中已经合并柔和投影和底部接触阴影，运行时每颗珠子只绘制一次。
- 异形珠：先绘制一张通用接触阴影，再根据珠子图片的透明轮廓生成一张阴影贴图。同一图片地址只生成一次。

第一版使用材料分类和已有字段判断异形珠：

- `category = 配饰`
- `isPendant = true`
- `isSpacer = true`
- `hangsOutward = true`

不满足以上条件时按普通圆珠处理。当前材料接口的大部分配饰没有返回三个布尔标记，因此配饰分类必须作为主要判断条件。图片内容不参与类型识别；图片透明区域只负责形成异形阴影轮廓。

## 渲染流程

每次重绘按以下顺序执行：

1. 统一计算珠子的显示直径并取得已加载图片。
2. 先绘制全部珠子的阴影。
3. 再绘制全部珠子图片。

阴影和图片使用同一份位置、旋转和显示尺寸，避免收串或缩放转换时出现错位。异形轮廓会跟随珠子旋转，但投影始终向画布右下方偏移，保持光线方向一致。

## 缓存与降级

- 普通圆珠阴影只缓存一张。
- 异形阴影按图片地址缓存，最多保留 40 张，超过后删除最早加入的一张。
- 图片尚未加载完成时，异形珠先显示通用接触阴影。
- 设备不支持离屏 Canvas 时，直接绘制简单椭圆阴影，页面仍可正常使用。
- 页面销毁时清空全部阴影引用。

这里不做缓存分桶、最近最少使用算法、每帧生成队列或预热策略。DIY 场景最多约 40 颗珠子，固定 160×160 模板已经足够，继续细分只会增加维护成本。

## 代码组织

- `pages/diy/engine/bead-shadow.ts`：类型判断、阴影贴图创建、缓存和绘制。
- `pages/diy/engine/renderer.ts`：准备珠子绘制数据，依次执行阴影和珠子两遍绘制。

不引入第三方阴影库。Konva、Fabric.js 和 PixiJS 都会带入新的渲染体系，却不能直接解决小程序里的珠子接触阴影和 PNG 透明轮廓问题。当前原生 Canvas 2D 方案更小，也更容易维护。

## 验收重点

- 普通圆珠有柔和投影，底部不悬空。
- 吊坠、隔片等异形珠的阴影跟随透明轮廓和旋转。
- 散珠、拖动、收串和展示转换期间，阴影位置与珠子一致。
- 相邻珠子的阴影位于全部珠子下方，不覆盖珠子表面。
- 40 颗珠子持续运动时没有明显掉帧。
- iOS、Android 真机以及微信开发者工具均能创建并绘制离屏阴影；不支持时会使用椭圆降级。
