# 订单物流与售后完整测试用例

更新时间：2026-08-04  
适用项目：`miniprogram-2 + backend-node + web-mall-manage`

## 一、先看这里

本轮最重要的验收目标：

1. 后台填写物流并发货后，订单变成“已发货”；
2. 发货信息成功同步到微信发货信息管理；
3. 用户在小程序“我的订单”中能查看并复制物流单号；
4. 退货退款审核通过后，用户必须填写寄回物流；
5. 后台收到寄回物流后，才能确认收货并发起微信退款；
6. 支付、发货、售后、退款状态在小程序、后台和微信侧保持一致。

当前不包含快递100等付费实时物流轨迹，因此不测试“已揽收、运输中、派送中”等节点。当前页面展示快递公司、快递单号、发货时间，并支持复制单号。

### 本轮修复后只需复测这 5 项

- [ ] 待发货订单卡片同时显示“填写发货”和“查看详情”；
- [ ] 从订单详情点击“填写物流并发货”，弹窗显示在详情抽屉上方并可正常输入；
- [ ] 对已发货但微信同步失败的订单点击“重新同步”，状态变为“已同步微信”；
- [ ] 售后申请页“添加凭证”区域不再出现被拉伸的原生加载图形；
- [ ] 对已经填写寄回物流的退货退款订单点击“确认收到退货并退款”，微信能够正常受理退款。

不需要重新创建或重新发货订单 A。微信发货信息使用原订单的“重新同步”验证；退款使用原售后订单再次点击退款验证。

## 七、权限与异常用例（不需要人工测试）

这一部分用于验证：即使有人绕过页面直接伪造接口请求，也不能查看别人的订单、修改别人的退货物流、重复发货或在条件不满足时退款。你不需要准备第二个微信号逐项操作。

订单归属、退货物流归属、未审核提交、不支持的快递公司、重复发货和缺少寄回物流退款均已由后端自动化测试覆盖；12 个测试文件、228 项测试全部通过。下面的明细仅作为后端安全规则说明，不列入本轮人工验收。

### SEC-01：其他用户不能查看物流

### SEC-02：其他用户不能提交退货物流

## 十二、确认收货与后台手动同步

本功能不运行定时任务。用户主动确认时立即核验微信状态；用户未主动确认时，等待微信自动确认后由管理员手动同步。

### RC-01：取消官方确认收货

1. 准备一笔已支付、已同步微信发货信息且本地状态为“待收货”的订单；
2. 真机进入“我的订单”，点击“确认收货”；
3. 在微信官方确认收货页面取消。

预期：

- [ ] 返回小程序并提示“已取消确认收货”；
- [ ] 订单仍为“待收货”；
- [ ] 后台订单仍为“已发货”。

### RC-02：用户主动确认收货

1. 对待收货订单点击“确认收货”；
2. 在微信官方页面完成确认；
3. 返回小程序等待状态刷新。

预期：

- [ ] 小程序提示确认收货成功；
- [ ] 订单状态变为“已完成”；
- [ ] 物流页不再显示确认收货按钮；
- [ ] 后台订单同步显示“已完成”；
- [ ] 重复进入订单页面不会再次显示确认收货按钮。

### RC-03：管理员同步尚未自动收货的订单

1. 准备一笔微信仍处于“已发货”的订单；
2. 后台订单管理点击“同步微信收货状态”；
3. 确认执行并查看汇总提示。

预期：

- [ ] 该订单计入“仍待收货”；
- [ ] 本地订单保持“已发货”；
- [ ] 不会仅按本地发货时间提前改成“已完成”。

### RC-04：同步微信自动确认收货订单

1. 等待微信按平台规则自动确认收货；
2. 后台订单管理点击“同步微信收货状态”；
3. 查看订单列表和详情。

预期：

- [ ] 微信已确认收货、交易完成或资金待结算的订单计入“更新完成”；
- [ ] 本地状态变为“已完成”；
- [ ] 详情显示“完成同步时间”；
- [ ] 单笔查询失败不会阻止其他订单同步；
- [ ] 汇总准确展示检查、更新、等待、跳过和失败数量。
